# Savings comparison

`/savings` evaluates three defined candidates using the existing adjudication engine: hypothetical additional Commercial AWP discounts, Retail Level 1 copays +$1, and Retail Level 2 maximum +$5. It is deterministic candidate evaluation, not an LLM discovering arbitrary interventions. Discount changes require new negotiated terms; these are not claimed to be available Caremark rates. Network moves and drug substitutions are not modeled.

The reference book remains separate from the 250-life Caremark planning calculator. A stable 1% sample preserves complete member claim histories through the selected day; results show actual evaluated claim/member counts and period savings, never projected whole-book member counts or annual savings. Net claim cost includes estimated rebates with service fees held constant. Savings percentages use net claim cost; guarantee settlements are not recalculated and require financial review. No-op replay must reproduce stored results before comparing candidates. Changes in the sampled source totals during a run stop analysis.

Disruption counts unique people with a higher-cost fill or a newly rejected paid fill. Reversed fills are removed before counting. Multiple reasons count once. Lower member costs and plan-only financial changes are not disruption. Each member links to all affected reference claims. Estimated NPS uses the existing paired census rubric, not observed survey data. Qualifying recommendations meet all supplied goals; any member cost increase fails the default rule even if aggregate member expense falls. New rejections always require clinical review and are excluded from recommendations.

POST /api/savings accepts a UUID requestId and goals (savingsPercent, maxDisruptedPercent, maxNpsLoss, allowHigherCost). It creates a persistent savings-v1 job, with idempotent retries for identical inputs. GET accepts id and returns recorded progress and results. Both interfaces are demo gated, authenticated by the existing application gate, and scoped to the configured sponsor/contract. The existing background worker processes the job, with single-attempt failure reporting. Saved run URLs resume inspection after navigation or reload.

Review in change console loads the exact server-recorded override. Imported retail scope is retained until a user edits a lever; the UI explains that editing switches to the console's custom configuration. A full-book replay is available through the existing job workflow and now honors the selected clock. No approval, implementation, or real savings is claimed by the comparison itself. Existing change-console commits record configuration and replay results; they do not establish external activation.

Performance changes: optional copy-editor metadata streams after page content; shared loading states unblock navigation; experience recommendations on /changes run only when requested instead of scanning claims on every visit. Savings computations run in the worker, not on page load.
